# TinkerPro Support — iOS setup

This Flutter project was scaffolded for iOS on a Linux dev machine, so the
*code* is iOS-ready but the *build* and *push notification setup* must
happen on a Mac. This file is your end-to-end recipe.

## Prerequisites on the Mac

1. **macOS 13+** with the latest Xcode (16+ recommended). `xcode-select --install` for the command-line tools.
2. **CocoaPods**: `sudo gem install cocoapods` then `pod --version` to verify.
3. **Flutter SDK**: same channel/version as the Linux dev machine (Flutter 3.x). `flutter doctor -v` should pass for iOS.
4. **Apple Developer Program account** ($99/year). A free Personal Team works for *side-loaded* installs that re-sign every 7 days, but FCM and TestFlight need a paid account.

## First-time setup checklist

```bash
git clone <this-repo>
cd flutter_app
flutter pub get
cd ios
pod install
cd ..
open ios/Runner.xcworkspace        # always the workspace, NOT the .xcodeproj
```

In Xcode:

1. Select the **Runner** target → **Signing & Capabilities** tab.
2. Set **Team** to your Apple Developer team. The bundle identifier should
   already be `com.tinkerpro.support` (matches the Android `applicationId`).
3. Add capability **Push Notifications** (required for FCM).
4. Add capability **Background Modes** → enable **Remote notifications**
   (already declared in `Info.plist` as `UIBackgroundModes`, but Xcode also
   needs the entitlement).

## Firebase / FCM on iOS

Push notifications on iOS go through APNs, so the existing Android
`tinkerpro-5ec76` Firebase project needs an iOS app added.

1. Open https://console.firebase.google.com → project **tinkerpro-5ec76**
   (or whatever the active one is).
2. **Add app → iOS**. Bundle id: `com.tinkerpro.support`. App nickname:
   "TinkerPro Support iOS". Skip the App Store ID for now.
3. Download **`GoogleService-Info.plist`** and drop it into `ios/Runner/`
   in Xcode (drag-and-drop, *not* via Finder — Xcode needs to add it to
   the **Runner** target).
4. **APNs auth key**:
   - Apple Developer Portal → **Keys** → **+** → name "TinkerPro Support APNs"
     → check **Apple Push Notifications service (APNs)** → Continue → Register.
   - Download the `.p8` file (one-time download — save it!). Note the
     **Key ID** and your **Team ID**.
   - Firebase Console → Project settings → **Cloud Messaging** tab → under
     the iOS app section, **Upload APNs Authentication Key**. Paste the
     Key ID and Team ID, upload the `.p8`.
5. In Xcode, edit `ios/Runner/AppDelegate.swift` to register for remote
   notifications on launch. The `firebase_messaging` plugin handles most
   of this automatically, but APNs registration is opt-in:
   ```swift
   import UIKit
   import Flutter
   import UserNotifications

   @main
   @objc class AppDelegate: FlutterAppDelegate {
     override func application(
       _ application: UIApplication,
       didFinishLaunchingWithOptions launchOptions: [UIApplication.LaunchOptionsKey: Any]?
     ) -> Bool {
       if #available(iOS 10.0, *) {
         UNUserNotificationCenter.current().delegate = self as? UNUserNotificationCenterDelegate
       }
       application.registerForRemoteNotifications()
       GeneratedPluginRegistrant.register(with: self)
       return super.application(application, didFinishLaunchingWithOptions: launchOptions)
     }
   }
   ```

## Build + run

```bash
# Local debug install on a connected iPhone:
flutter run -d <device-id>

# Release build for TestFlight / App Store:
flutter build ipa
# Output: build/ios/ipa/TinkerPro Support.ipa
# Upload via Xcode's Organizer or `xcrun altool`.

# Local install via Xcode (recommended for first-time signing):
# Open ios/Runner.xcworkspace, set device target, hit Run.
```

## Differences from Android — what won't work the same way on iOS

| Feature | Android | iOS behaviour |
|---|---|---|
| **Chat-head bubble** (Messenger-style floating window) | ✅ via Bubbles API + `ChatBubble.kt` | ❌ **No equivalent.** Chat pushes render as standard banner / lock-screen notification. The Dart `_tryShowBubble` returns `false` on iOS via `MissingPluginException` and falls back to `flutter_local_notifications` automatically. |
| **Foreground FCM** | data-only payload + client decides | Same on iOS once APNs is wired. |
| **Camera / gallery / file picker** | runtime permission prompt | Same — but the prompt text is what's in `Info.plist` `NSCameraUsageDescription` etc. (already populated). |
| **Open downloaded chat attachments** | `OpenFilex` opens via Android intent | `OpenFilex` on iOS uses `UIDocumentInteractionController` — works but the user has to tap "Open in…" to choose the target app. |
| **Adaptive launcher icon** | foreground + background layers | iOS uses the standard `Icon-App-*.png` set, generated by `flutter_launcher_icons`. |

The native `ChatBubble.kt` and `MainActivity.kt` files do **not** ship in
the iOS build (they live in `android/app/src/main/kotlin/` and are
ignored on iOS). No code changes required.

## Known gotchas

- **Pods version drift:** if `flutter pub get` upgrades a plugin, run
  `pod install --repo-update` in the `ios/` folder. Don't commit
  `Podfile.lock` from the Linux machine — that file is Mac-only.
- **`Info.plist` `NSAppTransportSecurity`:** the chat backend (`api.php`)
  is over plain HTTP for the dev environment. Either move the backend to
  HTTPS (recommended), or add an ATS exception for the host:
  ```xml
  <key>NSAppTransportSecurity</key>
  <dict>
    <key>NSAllowsArbitraryLoads</key>
    <false/>
    <key>NSExceptionDomains</key>
    <dict>
      <key>your-backend-host.com</key>
      <dict>
        <key>NSExceptionAllowsInsecureHTTPLoads</key>
        <true/>
        <key>NSIncludesSubdomains</key>
        <true/>
      </dict>
    </dict>
  </dict>
  ```
- **Soketi WebSocket:** if the WebSocket is also `ws://` (not `wss://`),
  the same ATS exception applies. The cleanest fix is to terminate TLS at
  an nginx in front of Soketi.
